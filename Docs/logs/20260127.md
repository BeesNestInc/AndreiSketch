# 作業日誌 2026-01-27

## タスク
オンプレミスPostgreSQL直結Jupyter基盤の最小構成構築

## 目的
Node.js (Fastify) からオンプレPostgresをDuckDB経由でマウントし、
フロント (Svelte) からSQLを投げて結果を表示する最小限の「一気通貫」を確認する。

## 実施内容
- **バックエンド (src/index.js):**
  - Fastifyサーバーを構築し、`/api/query`エンドポイントを作成。
  - DuckDBの`postgres`拡張機能を利用して、PostgreSQLデータベースに`ATTACH`する機能を実装。
  - クライアントからのSQLクエリを実行し、結果をJSONで返す処理を実装。

- **フロントエンド (front/):**
  - 当初Observable Frameworkで実装を進めたが、ユーザーの意図と異なったため方針転換。
  - Viteを使い、Svelteプロジェクトを新規に構築。
  - SQL入力用のテキストエリアと実行ボタンを持つ`Editor.svelte`コンポーネントを作成。
  - APIサーバーにクエリを送信し、結果（データまたはエラー）を画面に表示する機能を実装。

- **開発環境:**
  - `concurrently`を導入し、`npm run dev`でバックエンドとフロントエンドの開発サーバーが同時に起動するように`package.json`を修正。

## 発生した問題と解決策
実装過程で、複数の問題に直面し、それらを段階的に解決した。

1.  **Observable Frameworkのルーティングエラー:**
    - **問題:** `Not found: /index`と表示され、ページが描画されない。
    - **原因:** `observablehq.config.js`の`root`設定が、実際のファイル配置(`Observable/`)と異なっていた(`src`)。
    - **解決:** `root`を`"Observable"`に修正。

2.  **Svelteコンポーネントがレンダリングされない:**
    - **問題:** `<svelte:component>`タグがそのまま文字として表示される。
    - **原因:** プロジェクトに`svelte`パッケージが直接インストールされていなかったため、Observable Frameworkがコンポーネントをコンパイルできなかった。
    - **解決:** `npm install --save-dev svelte`を実行。
    - **方針転換:** 最終的にこのアプローチは破棄し、Vite + Svelte構成に移行。

3.  **`@formkit/tempo`のインポートエラー:**
    - **問題:** `SyntaxError: The requested module '@formkit/tempo' does not provide an export named 'Tempo'`
    - **原因:** `Tempo`クラスではなく、`format`などの関数を名前付きインポートする必要があった。
    - **解決:** インポート文を`import { format } from '@formkit/tempo'`に修正し、呼び出し箇所も`format(...)`に変更。

4.  **DuckDBの`ATTACH`文の構文エラー:**
    - **問題:** `Parser Error: syntax error at or near "amazon"`
    - **原因:** 接続文字列をさらにシングルクォートで囲んでいたため、SQLの構文エラーが発生していた。
    - **解決:** 接続文字列から不要なクォートを削除し、`dbname=... user=...`の形式に修正。

5.  **`BigInt`のJSONシリアライズエラー:**
    - **問題:** `TypeError: Do not know how to serialize a BigInt`
    - **原因:** DBからの結果に`BigInt`型が含まれており、`JSON.stringify`が対応していなかった。
    - **解決:** サーバーがレスポンスを返す直前に、`BigInt`型の値を`toString()`で文字列に変換する処理を追加。

以上のデバッグを経て、最終的に要件通りの一気通貫動作を確認できた。
